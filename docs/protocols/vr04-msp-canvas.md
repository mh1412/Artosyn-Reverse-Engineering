# VR04 reference MSP canvas and FC telemetry

[Protocols](README.md) · [Reference link control](../systems/vr04-link-control.md)

## Three separate boundaries

The reference air unit receives flight-controller DisplayPort messages over a
serial MSP connection, repacks them into an Artosyn canvas, and sends that canvas
to the goggle as message type `0x10` on UDP 10000. The stock goggle exposes canvas
bytes through shared memory; the open receiver forwards the radio frame to its
HUD through [MLM IPC](mlm-ipc.md). These are different envelopes around related
content, not one interchangeable MSP packet format.

This article consolidates the retained binary-analysis narrative and inspected
MissingLynk implementation at `674ec00ecde0bba2eb844def1b4a0b7f8e685e13`.
Hardware observations are reported from the original research. The host capture
checks described below were rerun during this documentation review.

## Stock shared-memory access

The recovered `GetOsdContext` command is transaction `0x2c`. Its 12-byte raw reply
contains control return `u32` at +0, canvas offset `u16` at +4, byte length `u16`
at +6 and symbol/sequence ID `u32` at +8. The canvas itself is not in that reply.

Transaction `0x31` returns an OSD System V shared-memory ID at +4 and a media ID
at +8. The client attaches the OSD ID with `shmat` and reads `base + offset` for
the returned length. The IDs are neither sizes nor keys. The optional AI overlay
uses transaction `0x39` to obtain its ID and `0x3a` for its context; detach uses
`shmdt`. The research reports an on-device client reproducing this handshake.

The vendor library wraps the result in a caller object with symbol ID at +0,
pointer at +8 and length at +16. That object is not the 12-byte transaction reply.
The separate [stock UI study](vr04-stock-ui.md) retains the observed blocking
behavior of context polling and other IPC limits.

## Canvas packing

The transport inserts `0xff` **after each pair of original bytes**, leaving an
odd final original byte alone. Removing the known separator positions recovers
the plain canvas. Blindly deleting every byte equal to `0xff` is not equivalent
when actual content contains that value.

| Plain offset | Field |
| --- | --- |
| 0 | One-byte record count |
| 1–4 | Big-endian 32-bit canvas sequence |
| 5–8 | Big-endian 32-bit total plain length, including this nine-byte header |
| 9 onward | Length-prefixed write-string records |

A record can be expressed without the ambiguous “chain byte belongs to both
records” terminology:

```text
length  b6 03  row col attr  glyph[0] ... glyph[g-1]
```

The declared **length is `4 + g`**, for every record including the last. The
whole record occupies `6 + g` plain bytes, including its length and `b6` command
byte. Another record starts immediately afterward. Equivalently, the byte before
each next `b6 03` is the next record's length; it must not render as a glyph.
The final record has no following length byte. Six glyphs such as `DISARM`
therefore declare length 10, even though only nine bytes follow the `b6 03` marker.

This explains an earlier encoder off-by-one: treating the last record's declared
length as the number of bytes after its marker emitted 9 instead of 10. A parser
that merely rescans for markers can overlook this transmitter error.

For the retained worked header `06 00 00 03 91 00 00 00 51`, the record count is
6, sequence 913 and total plain length 81. A following `0a` is the first record's
length, not a tenth header byte. Pair interleaving expands 81 plain bytes to 121
bytes. This worked sample is separate from the 68-frame fixture checked below.

The observed grid is **53 columns × 20 rows**. The earlier worked sample places
voltage and flight time at column 2, `MANUAL` and `FAST` at column 43, and cleared
cells near column 23. All observed attributes in the checked fixture are zero.
Page, blink and color behavior for nonzero attributes remains unqualified.

## Who renders the stock canvas

The stock service exposes the canvas, but the Qt `test_uidesign` UI paints its
glyphs. The recovered UI loop obtains context, unpacks symbols, and emits
`osdcontentsenduint(x, y, glyph, state)` to QML. That fourth argument is add/clear
state, not the canvas attribute. The inspected path carries attributes opaquely
and drops them before rendering.

Other stock VO/VENC overlay queues carry system, AI or RC graphics and do not
establish that removing the Qt UI leaves this flight-controller canvas visible.
A replacement UI must render it. In the open stack `ml-linkd` owns UDP 10000;
the HUD receives forwarded frames and does not compete for that port.

The renderer uses a PNG glyph atlas with 256 vertically stacked 24×36 glyphs.
The recorded default was generated by doubling a 12×18 font; the asset is loaded
separately rather than baked into the executable. The older renderer scaled a
whole native glyph canvas to avoid fractional per-glyph seams. The later HUD
tracks cell changes and updates their rectangles. A configurable loader does
not by itself prove that the custom-font selection menu was implemented.

The retained source font is the Betaflight MAX7456 character map: 256 glyphs,
12×18 pixels, two bits per pixel. Value 0 is black, 2 is white, and 1/3 are
transparent. Its asset note attributes the font to Betaflight Configurator
under GPLv3; that provenance belongs with any redistributed atlas. The note
explicitly defers custom-font loading from SD.

## Open air-side client

The inspected client defaults to `/dev/ttyS1`, raw 115200 baud, eight-bit data,
and nonblocking I/O. It accepts **MSPv1 reply framing `$M>` only**, with XOR over
length, command and payload. Literal `$X` input gets a one-time v2 diagnostic and
is skipped; v2-over-v1 command 255 is not interpreted. The narrative's broader
MSPv1/v2 description of the vendor protocol is not the open client's capability.

| Request / input | Implemented handling |
| --- | --- |
| Status `0x65`, every 200 ms | With at least 7 payload bytes, arm state is bit 0 of byte 6 |
| Battery `0x82`, every 5000 ms | With at least 11 bytes, consumed mAh at +4 is multiplied by 10; voltage at +9 is multiplied by 10 to mV |
| DisplayPort `0xb6` | Clear 2 resets accumulated records; write 3 appends row/column/attribute/text; draw 4 emits a canvas |
| API-version `0x02` reply | Updates the general presence timestamp |

The implementation buffers 512 receive bytes, 384 internal record bytes and
emits through 512-byte plain/768-byte packed scratch buffers. It trims a trailing
NUL from a write string and clears records after drawing. A zero-record draw
does not emit an empty canvas. Its storage limits and append behavior do not
prove complete equivalence to every vendor update/clear sequence.

Presence uses a 15-second freshness window. Status, battery and API-version
handling update that timestamp; **DisplayPort alone does not**, despite an older
comment saying any reply does. No FC and a disarmed FC both leave an arm value
of zero, so policy must also consult presence. Battery freshness is tracked
separately. A fresh FC voltage **greater than 1800 mV** overrides the SoC ADC;
1800 is an override threshold, not a clamp or general plausibility floor.
The open expiry/fallback policy differs from the reported vendor behavior of
retaining the last FC value indefinitely.

## Host verification and parser limits

The retained capture fixture has SHA-256
`ad49559cd1b6f1cf44219aae867dc881b4836a43ff62730a49307e6c9453c3dc`.
The existing host round-trip test passed **68 canvases, zero mismatches**. It
decodes each captured canvas, reconstructs MSP input, runs the real air encoder,
and requires byte-for-byte equality with the captured canvas. Sequence is seeded
from the fixture; the test does not validate free-running sequence behavior.

A separate positional unpack/length walk traversed 176 capture records and
checked all 68 incoming canvas payloads: counts, declared lengths, marker
positions, separator positions and total lengths agreed. Sequences were 0–67;
attributes were all zero; no plain canvas contained a literal `0xff`. Other
packet families in the file were not semantically reviewed by that check.

The inspected HUD parser removes every `0xff` and scans for `b6 03`, rather
than validating header count/length and walking declared records. Small host
probes confirmed that an ordinary glyph `41` survives, a content glyph `ff`
disappears, and content glyphs `b6 03` are mistaken for a structural marker.
These demonstrate implementation limits for synthetic inputs, not newly observed
faults on a flying system. The captured corpus does not cover them. The fixture
test also skips canvases that decode to no records, so its summary count alone
is not proof that arbitrary canvas fields or malformed inputs are handled.

Nonzero attributes, all glyph values, empty-canvas clearing, sequence bytes that
contain separator/marker values and broader FC variants remain coverage gaps.
