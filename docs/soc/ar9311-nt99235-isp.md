# NT99235 ISP reconstruction, statistics and adaptive state

[SoC studies](README.md) · [Camera path](ar9311-nt99235-camera.md)

## Evidence and reproducibility boundary

This study concerns the NT99235 reference pipeline at the
[pinned MissingLynk kernel revision](../references/README.md#platform-and-application-references).
The vendor's userspace library names 65 ISP submodules. Their attach handlers
identify register banks; apply handlers generally update a register shadow and
write changed words. Module names alone are insufficient: two statistics modules
register under duplicated names, and several blocks share a bank.

The retained provenance classifier reports **1,260 distinct ISP offsets in its
table model**, labeling 1,258 as regenerable and two as hardware-owned values
needing further device evidence. An offline rerun reproduced those counts and
zero unexplained entries. This is a classification result, not a complete
executed-write inventory or a numerical reconstruction of all 1,258 values.
The [audit limitations](#what-the-provenance-count-covers) below matter when using
the headline. CVISP has a separate derivation, retains recorded residues, and
still takes write order from a trace.

| Input | What it supplies | Boundary |
| --- | --- | --- |
| NT99235 tuning blob | Shading, black level, tone curves and adaptive ladders | Sensor-specific layout; equal-sized SC2210/SC231 blobs are not interchangeable |
| `libmpp_service.so` | Static bank images, packers, descriptor ownership and control flow | Virtual addresses are tied to the studied binary |
| Ordered MMIO traces | Actual writes, ordering and buffer cadence | Captured process/window only; a store-only trace reveals no polling |
| Live registers and DMA captures | Operating-point comparisons and buffer structure | Hardware state, stale memory and allocation tails require separate treatment |

The implementation installs ordered setup, then derives and republishes its own
state. This ordering matters: the applied 1,475-entry setup prefix can overwrite
early descriptor publication and omit later runtime matrices or curve tails.
Replacing a blob/library requires regeneration and comparison against the new
input; copying an old captured address or operating point is insufficient.

The examined AEC/AWB/AF algorithms execute in the ARM service process. Located
DSP calls belong to an optional AI-ISP/NPU path, and the studied FPV rootfs
contains no DSP program image for it. That supports the recorded absence of a
DSP participant in this configuration; it does not identify every firmware's
3A execution architecture.

## What the provenance count covers

The reproduced main-ISP tally is:

| Class | Distinct offsets |
| --- | ---: |
| Derived from tuning, by stage membership | 233 |
| Equal to a checked-in library image word | 680 |
| Explained by an entry in the recovery map | 114 |
| Stage gate | 1 |
| Zero write | 148 |
| Geometry/grid numeric pattern | 16 |
| Vendor DMA address range | 20 |
| Hardware-owned | 2 |
| Vendor static block, by stage membership | 46 |
| Disabled stage / device capture with no other source / unexplained | 0 / 0 / 0 |

The model collapses `kept → full setup → trim` by last write, then removes the
hardware-owned skip list. The actual default startup uses a prefix and output
arm, followed by dynamic appliers. The model does not execute those functions,
evaluate parameter-dependent branches, track write timing or enumerate every
later descriptor/IRQ write.

There is a concrete skip-list mismatch: the driver filters that list in its
**trim** pass, while the audit removes its offsets globally. Full setup still
contains `0x00cc`, `0x0834`, `0x08a8` and `0x2838`; all except `0x08a8` also
occur within the default 1,475-entry prefix. This does not make each write a
defect—`0x00cc` is W1C status—but it prevents interpreting 1,260 as an exhaustive
count of registers the driver writes.

Classification also differs from arithmetic validation. Stage membership earns
the derived/static labels without running the builder, and an `EXPLAINED` entry
accepts its offset without checking the current value against that explanation.
An in-memory test changed modeled `0x0004` to `0xdeadbeef`; the audit still
returned success. The separate geometry checker would be needed to reject that
value. Likewise, geometry-shaped numbers and the DMA address range are
classification heuristics, not proof of a field's meaning or buffer ownership.
The [runtime fallback paths](ar9311-nt99235-isp-runtime.md#startup-success-and-degraded-operation)
can leave vendor addresses in place when allocation fails.

The two retained hardware-owned words are `0x6518` and `0x651c`, both carried as
1. Stable snapshot agreement does not settle whether the hardware produces that
value or the driver's write does; the requested wider A/B measurement remains
open. Zero unexplained entries therefore does not mean zero captured values.

The combined audit's CVISP subsection counts residues and unclassified words
but discards the classifier's separate composition-mismatch list. A synthetic
unity-gain value of 123 at `0x4600` produces a mismatch against zero while adding
neither a residue nor an unclassified entry. The dedicated CVISP checker tests
that mismatch; the combined headline alone does not. Its passing thresholds
also explicitly permit two main-ISP device-dependent words and eight CVISP
residues. These scope tests changed no source file or hardware state.

## CVISP table provenance and verification limits

CVISP's separate tables contain **255 setup writes, 101 late writes and eight
maintenance writes**, plus five ring address triplets. Last-write-wins analysis
of those tables produces 331 distinct register offsets:

| Provenance class | Registers | Interpretation |
| --- | ---: | --- |
| Library images | 263 | Matches the extracted static templates |
| Geometry / port scoreboard / zero / unity gain | 40 | 3 / 1 / 4 / 32 respectively |
| Carried BLC constants | 16 | Replaced only when the enabled tuning pass succeeds |
| Class labeled “vendor DRAM address” | 4 | Three plane bases and one stride; not four addresses |
| Recorded residues | 8 | Values still depend on the observed trace |

The four-word address class includes `0x809c=0x800`, a stride that queue arming
does not replace. Only `0x8098`, `0x8174` and `0x8194` are the three plane bases.
The checker's description of all 20 carried words as overwritten “before they
matter” is therefore too broad. Setup also enables output before the late table
and BLC pass execute. The ordering remains trace-derived.

The final eight residues are:

| CVISP offset | Recorded value | Remaining question |
| --- | --- | --- |
| `0x8000` | `0x00800806` | Meaning of staged enable bits 1 and 2 |
| `0x802c`, `0x8054`, `0x80cc`, `0x80f4` | `0x08000b32` | Descriptor field with template bit 0 cleared |
| `0x8144` | `0` | Configuration versus teardown residue |
| `0x81b4` | `0x04000400` | Q10 unity interpretation; writer not recovered |
| `0x81c8` | `0x03000030` | Low-bit changes not explained by the located writer |

Older generator prose says nine residues. The final-state checker reports eight;
individual ordered writes include additional intermediate residues later replaced
by library values. Neither count means every descriptor field is decoded.

An offline reproduction regenerated both the extracted library header and the
derived setup header byte-for-byte using the pinned `libmpp_service.so`, SHA-256
`4cfc8e6cfb42d8c821137993b95b152f1aaad7c53ce425e6a0493c4dd453936c`.
The library extraction covers 277 template register entries. The setup generator
checks the binary identity but obtains values from the extracted header, so both
generation steps matter. The 32 hexadecimal characters printed in the header
are a truncated SHA-256, not a different hash algorithm. Another retained library
with the same filename has a different full hash and is not this input.

The derivation checker passed in this reproduction **without its slot-A live
captures present**. Its exit status checks composition and unclassified values;
missing or differing measurements do not themselves fail it. Explicit residue
classes accept recorded values by design. Thus this result establishes offline
reproducibility of the tables, not fresh vendor/open register agreement, removal
of all replay dependencies, or hardware capture validation.

## Register attribution and corrected interpretations

Offsets below are relative to ISP `0x08c00000`, except explicitly marked CVISP.

| Bank or register | Recovered role |
| --- | --- |
| `0x0004` | Input `{mode[27:26], height[25:13], width[12:0]}`; measured 1924×1084 |
| `0x0008` | Template geometry word; its apparent 1920×1080 decoding is not proof of a general computed format |
| `0x00c8`, `0x00d0` | Interrupt enable masks |
| `0x00cc`, `0x00d4` | Matching status registers, cleared with write-one masks in the later disassembly analysis |
| `0x2800` | Shared GTM2/LTM control, coefficient input and histogram output |
| `0x3400`, `0x3800` | CCM1 and CCM2 matrix banks |
| `0x4800` | Colour manipulation/clamp fields; distinct from CCM matrix banks |
| `0x4c00` | Lens shading |
| `0x5800` | Four-bank LUT3D stage |
| `0x6000` | Raw Bayer histogram |
| `0x6400`, `0x64c8` | Main and smaller-window RRO statistics |
| `0x6c00`, `0x7400` | AWB and autofocus statistics, disabled in the studied tuning |
| `0x7000` | Input/vsync monitor, previously misattributed to AWB statistics |
| CVISP `0x4200`, `0x4700` | Black-level subtraction and second digital-gain bank |

The earlier trace narrative called `0x00cc/0x00d4` an indirect access port.
Later analysis follows the **ISP base pointer** and identifies interrupt status
and W1C handling. Preserve the recorded write order, but do not propagate the
old port interpretation as an established register definition. The same offsets
on VIF belong to another block. No ISP reader/writer was located for `0x00ec`
in the inspected library and trace set.

The input monitor routes eight taps with selector values
`{0,3,8,14,15,23,22,31}`, spanning input, HDR, noise, colour and scaler paths.
Its `0x7054` value varies as a live counter; `0x705c` includes the vendor-named
`ro_blank_h` status. A captured word is not automatically a writable setting.
Even a configuration word can mix ownership: `0x7058` preserves hardware bits
14 and 19 in vendor read-modify-write operations.

Writing a stage bank does not prove the stage runs. The reference gate table
has unresolved polarity/ownership, including RNR/BIRNR sharing an assigned gate
despite differing tuning enables. HDR has no second exposure, raw 3DNR is
disabled, and LUT3D is installed but disabled. AWB is gated off, so white balance
is unity and the observed CCM1 matrix is static. LTM enable bits 4 and 11 were
corroborated by control values `0x00060770 → 0x00060f70`; its adaptive producer
still remains incomplete.

## Coefficient pages and memory ownership

Allocation size, flushed size and fetched extent must be distinguished.
An address gap can describe an allocator slot containing neighboring or stale
data; it does not establish a meaningful coefficient format.

| Payload | Descriptor | Established content and limitation |
| --- | --- | --- |
| ISP lens shading | `0x4c34`, length `0x4c28`, valid `0x4c3c` | `0x340` bytes: 50 grid records plus two zero records; slot remainder is not shading |
| Gamma | `0x0030/0x0040/0x0050` | Three aliases to one allocation; generated dynamic curve and fixed companion page |
| DRC | `0x0060` | `0x2000` rebuilt page; dynamic profile pairs plus fixed tail |
| Compander | `0x0020` | Library template with repeated unity/zero regions; stage is disabled here |
| HDR | `0x1c6c`, valid `0x1c60` | Disabled-stage page shares an allocation with compander; old fetched-extent accounts conflict |
| LTM | `0x2808` | `0x4000` bytes, 64 curves; alternates between two owned buffers |
| LTM statistics | `0x280c` | Histogram output, not a second coefficient input |

The recovery record contains contradictory gamma/HDR length arithmetic, including
an older 32-byte interpretation and later statements that mix `0x800` and
`0x1000` extents. The selected implementation explicitly documents gamma length
`0x80` as **16-byte records**, hence `0x800` bytes; it still builds a companion
page at `+0x800` in a `0x4000` allocation. Do not use the old prose to infer that
every byte of that allocation is fetched or that all descriptors have one unit.
The exact HDR over-fetch boundary remains a source-reconciliation issue; its
disabled state does not qualify an HDR operating mode.

Global commits use `0x0014`: compander bit 0, gamma bits 1–3 and DRC bit 4,
with bit 16 set alongside. These are write-to-trigger operations; explicitly
clearing the bit afterward can cancel the fetch. Fill before publishing.
LSC/HDR use module-local valid fields instead of global selector bits.
Descriptors must be republished after any replay that restores old addresses.

DRC's first `0x1000` bytes comprise two `0x800` banks of 128 records. Each
16-byte record packs three unsigned 20-bit values in its first ten bytes;
duplication and overlap represent a 257-sample curve. The remaining `0x1000`
bytes are fixed. Strength is a separate software transform around neutral 50:
`floor(abs(strength−50) × 4096 / 50)` blends toward a fixed high/low curve before
packing. Reconstructing these bytes does not establish the physical meaning of
every bank.

### Lens shading and colour matrices

The ISP shading record holds four illuminant groups, each `0x678` bytes, with
four 10×10 float grids. Its temperature ladder spans
2,700/2,900, 3,700/4,300, 4,700/5,300 and 6,200/6,800 K.
Two grids reach the captured page: group 0 grid 1 in the duplicated field and
grid 0 in the third field. Grid 2 ties only where it is byte-identical to grid 1;
the fourth grid's consumer and full group-selection path remain unresolved.

Quantization is `floor(gain × 2048)`, packing adjacent points into 16-byte
records of two `(a,a,b)` triplets. Truncation matches all 100 grid points,
where rounding matches only 55. The rebuilt `0x340` bytes matched two captures.
Fetch length is independently supported by the `0x34` record count and
`0x340` flush. Strength/enable at `0x4c40` is bit 16 plus Q7 strength: tuning
strength 0.5 and enable 1 give `0x00010040`. A different readback phase is not
proof that this later applied value was absent.

CCM matrices are registers, not DMA tables: a 3×3 matrix packs into six words
using 16-bit sign-magnitude Q8 coefficients truncated toward zero. CCM1's
initial identity is replaced by tuning bank 0 in the observed runtime;
CCM2 retains its static library matrix with its tuning gate off. Its illuminant
ladder is separate from shading's. The ISP RGB-to-YUV bank at `0x3c00` uses
BT.601 full-range coefficients; the VIF setup contains BT.709 limited-range coefficients in
a different stage. Those two tables do not establish one interchangeable colour
contract for the whole pipeline.

### Black level, geometry and gain ladders

Black-level subtraction occurs in CVISP even though the ISP BLC bank is off.
The reference derives it from five tuning bands, with a **pinned input 187**
matching the traced registers. A dark capture at much higher sensor gain did
not move the observed BLC values. This is operating-point agreement, not proof
of a recovered closed-loop BLC control law.

In the inspected CVISP driver, a missing or too-short tuning file leaves the
late table's constants in place and does not fail stream-on. The writable
`blc_gain` parameter is consumed during configuration; changing it does not
trigger a live update. The separate `fpn=true` option clears the FPN enable bit,
matching the recorded disabled state despite the parameter's name.

The offline BLC layout check passed for tuning SHA-256
`33fb86da0dc17a8c38570dbf3a13b6ef1bfe64a736560f47a03dc3f3cb5582b5`:
five 32-byte entries at `0xb4`, with five float-pair bands at `0x34`. This run
had no trace input and checked table/ladder structure only. Even the checker's
optional trace path checks primary lane ranges and scaling, rather than full
interpolation parity or all duplicated output registers. It is not an all-gain
comparison of the C implementation with the vendor's float arithmetic.

Five stages use a linear gain axis: RNR, LNR, DE3D, CFA and CNF. Inside a band,
the payload is used directly; gaps interpolate and truncate, and endpoints clamp.
Reported parity checks compiled the actual C headers and compared them with the
independent reconstruction. The 146-register joint fit for three stages narrowed
one captured gain to about 6.8857–6.8948. Sensor code `0x3c=14×` is not this axis.

DE3D geometry includes a padded width of 1,928, aligned work strides of 1,792
and 256, and separate full/half/small work buffers. A prior small-buffer
allocation was about 55 times too large. Read-modify-write masks distinguish
geometry fields from flags and ladder values; the low byte of `0x2e30`, for
example, belongs to the ladder. A line latch at `0x2e98` is hardware-owned.
LNR also had a truncated curve tail restored, but its strength mapping at
`0x3d14` remains incompletely recovered; matching one captured value cannot
close that gap.

## Statistics: what the per-frame addresses mean

The eight frequently rewritten ISP addresses are **seven statistics pointers
and one coefficient pointer**, not YUV frame planes. CVISP owns those planes.

| Register | Producer or consumer | Decoded extent |
| --- | --- | --- |
| `0x75a0`, `0x75bc` | AF statistics | Stage disabled here |
| `0x6440`, `0x6474` | Two RRO engines | Each points to a `0x4800` zone-grid layout; vendor aliases the buffers |
| `0x600c` | Raw Bayer histogram | First `0x800` bytes of a `0x1000` buffer |
| `0x280c` | LTM histogram | First `0x8000` decoded as 64×256 `u16` bins |
| `0x6508` | Smaller-window RRO engine | Same zone layout, different counts |
| `0x2808` | LTM coefficient consumer | 64×128 `u16` curve samples |

RRO is a 36-column × 16-row grid, column-major. Each column occupies `0x200`
bytes: `0x100` of counts followed by `0x100` of sums, four `u32` channels per
zone. Dividing sums by counts yields values up to exactly 255. Channels 1 and 2
track as the two greens; the red/blue ordering of 0 and 3 remains unresolved.
Counts 826 and 90 match window areas `118×28/4` and `36×10/4`; those zone
dimensions are not simply frame dimensions divided by the grid.

The raw histogram has 128 bins and four lanes. Totals are exactly
518,400 / 1,036,800 / 518,400 / 0 for the 1920×1080 frame, establishing Bayer
quarter/half/quarter populations and the unused fourth lane. Population counts
alone do not distinguish the two equal red/blue lanes; input bin width also
remains unresolved. AWB statistics had no established captured layout.

AF geometry was recovered despite the stage being disabled: a library-defined
window gives offset `(240,135)` and size 480×270 at this resolution, with
registers `0x740c=(135<<16)|240`, `0x7410=(30<<16)|30` and
`0x7414=(27<<16)|28`. Programmed geometry does not prove active autofocus.

## Tone selection and the remaining adaptive work

AE meters the RRO grid and drives exposure, sensor gain and ISP gain through one
exposure-table index. Recorded hardware validation covered the AE law and the
original RNR/LNR/DE3D actuation. CFA/CNF and broader gate qualification remain
bounded. The older claim that all seven ladder stages share one gain axis is
superseded: **CM and CM2 use the tone scalar**, alongside gamma and DRC.

| Stage | Recovered selector bands |
| --- | --- |
| Gamma | `[0,40]`, `[80,130]`, `[150,250]`, `[280,330]`, `[360,450]` |
| DRC | `[0,80]`, `[100,130]`, `[150,180]`, `[210,270]`, `[290,380]`, `[410,500]` |

Within a band the selector chooses one record. Across a gap it blends source
words as `(low × (4096−t) + high × t) >> 12`, using truncated Q12 `t`.
The open gamma builder blends the selected source positions `0,8,…,4088`, then
applies a monotonic clamp and separately blends endpoint 4095. Pointwise blending
and selecting those positions commute before the clamp; the comments' claim
that this selection order is inherently non-interchangeable is too broad.
DRC reconstruction
matched the full `0x2000` captured page; gamma retained a 0–5-count sampling
residual on a 4,095 scale, about one count on average.

The August 14 correction identified a DRC profile-3/profile-4 blend at weight
0.25, scalar **275**. The earlier nearest-curve reading of that session had
incorrectly constrained it to pure gamma 2/DRC 3. That invalidated earlier
exclusions of candidate scalar producers. Later simultaneous register sweeps
put the exposure-table index within roughly 0–2 counts of the tone scalar;
`exp_index` is the leading candidate, but downstream routing is not fully traced.

The open reference pins CM/CM2 at scalar **291**, selecting gamma curve 3 and
DRC profile 4 consistently. The older gamma-3/DRC-3 pair has no common band.
At 291, recovered CM/CM2 fields match observed vendor values, including CM
gain field 33 and clamp bounds `1/2/1006/1023`; the second reciprocal is
`1024/(1023−1006)=60`. This is not continuous tone adaptation. The inspected
AE work does not establish live updates of these pinned selectors, and
anti-flicker integration snapping remains unimplemented.

LTM uses an 8×8 grid of 128-sample curves, `0x4000` bytes total. Register
reciprocals uniquely support this layout; the packer operates on doubled tile
counts, giving 120×67 metering areas and a 75-pixel final row at 1080p.
The vendor computes curves using CLAHE. Only one retained page was a usable
coefficient reference, differing from an identity ramp by at most 34 counts
on a 1,016 scale. Other large dumps included unrelated heap data.

The open implementation has two `0x4000` halves and publishes the freshly
filled half. Its replacement-page interface commits on close when the greatest
written end position reaches the page size; that is not a contiguous-write or
exact-input-length check. The histogram interface exposes data for a future
producer. See [runtime controls](ar9311-nt99235-isp-runtime.md#tone-and-ltm-controls)
for upload, concurrent-access and in-place gamma/DRC update limits. The default remains
an identity curve. In particular, a `0x80000` captured/allocation span is not
all LTM statistics: the decoded histogram occupies `0x8000`, with vendor
allocation arithmetic yielding `0x8400` including extra space. The rest cannot
be promoted to a decoded format.

The remaining work is therefore both algorithmic and physical: complete tone
scalar routing, anti-flicker and CLAHE; qualify adaptive gates and scene changes;
resolve descriptor-length contradictions and CVISP reset/completion ownership.
The [validation record](../experiments/nt99235-camera-validation.md) explains why
register agreement and attractive images alone do not establish full parity.
The [runtime study](ar9311-nt99235-isp-runtime.md) also distinguishes successful
startup from complete buffer ownership and working interrupts.
See [coefficient formats](ar9311-isp-coefficient-formats.md) for the packed records,
fixed-curve reconstruction and independently checked library-byte comparisons.
